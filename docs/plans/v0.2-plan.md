# SOVRAN v0.2 — Detailed Implementation Plan

> Branch: `feat/trust-and-productivity` (from `main`) · Scope: **Wave 1** (trust & recovery) and **Wave 2**
> (productivity). Wave 3 and later are designed here but implemented in later branches. See [ROADMAP](../ROADMAP.md).

## Prioritization principle

**Recoverability before reach.** Local and mid-size models make more mistakes than frontier models. An agent is
used daily only if mistakes are *cheap to undo* and the user *understands its limits*, such as how full the context is.
That is why checkpoints, the context meter, retry and compaction come before MCP or new integrations: a powerful
agent the user does not trust gets switched off.

## Wave 1 — Trust & recovery

### F1. Checkpoints and run rollback

**UX.** After a response that changed files, the turn ends with a footer: `3 files changed · Undo changes`.
Undo restores every file to its state before that response, deletes files the agent created, and goes through
`WorkspaceEdit`, so the undo is itself undoable. If the user edited a file after the agent did, a native modal asks
"Restore anyway / Only unchanged files / Cancel".

**Changes:**

| Layer | File | Change |
|---|---|---|
| Core | `ports.ts` | `WorkspacePort.deleteFile(absPath)` |
| Core | `checkpoints/checkpoints.ts` *(new)* | `CheckpointRecorder` decorates `WorkspacePort` and snapshots each file before its **first** write in a run (existed? original content) plus the hash of the final content. `planRestore()` classifies files as clean, modified or missing. `restoreFiles()` |
| Core | `sessions/model.ts` | `UserMessage.checkpoint?: { id; files: string[]; restoredAt? }` |
| Host | `adapters/FsCheckpointRepository.ts` *(new)* | One JSON file per checkpoint (`<sessionId>--<id>.json`) in workspace storage. Deleted with the session |
| Host | `adapters/VscodeWorkspace.ts` | `deleteFile` through `WorkspaceEdit.deleteFile` (undoable) |
| Host | `SovranController.ts` | Wrap the workspace with the recorder per run. Persist the checkpoint and attach it to the user message. `restoreCheckpoint` handler with a conflict modal |
| Protocol | `shared/protocol.ts` | `restoreCheckpoint { messageId }` |
| UI | `Transcript.tsx` | Turn footer with changed-file count, *Undo changes* / *Changes undone* |

**Tests:** recorder (first-write snapshot, created and deleted files), restore (clean, modified, missing, skip
modified), webview footer actions.
**Risk:** large files bloat storage. *Mitigation:* tools already refuse files over 5 MB, and checkpoints are deleted
with their session.

### F2. Context meter

**UX.** The composer shows `18k / 32k` with a thin bar. It turns amber above 70 % and red above 90 %. The tooltip
explains the numbers, and clicking compacts the conversation.

| Layer | Change |
|---|---|
| Core `agent/events.ts` | `context` event `{ estimatedTokens, budgetTokens, contextWindow }` emitted per request. `usage` event when the server reports real `prompt_tokens` |
| Core `sessions/model.ts` | `Session.usage?: { tokens; contextWindow; source: 'estimate' \| 'server' }` |
| Host | Store the usage on the session and project `AppState.usage` |
| UI | `ContextMeter` component in the composer bar |

**Tests:** the runner emits `context` and `usage`. The meter thresholds and labels render correctly.

### F3. Retry, edit and rewind

**UX.**
- **Retry** appears on the last turn and on error blocks, and regenerates the response.
- **Edit** (pencil on any user message) edits the message inline and resends it. Every later message is removed.

If the removed turns changed files, a modal asks: *"Also undo N file changes made after this message?"* with the
options Undo and continue / Keep files / Cancel. This ties rewinding the conversation to rewinding the code.

| Layer | Change |
|---|---|
| Protocol | `retry {}` · `editMessage { messageId, text }` |
| Host | Split `sendPrompt` into `startRun(session, user)`. `rewindTo(index)` collects later checkpoints and restores them in reverse order, then truncates |
| UI | Edit affordance on user blocks (inline textarea). Retry buttons |

**Tests:** webview edit, retry and error-retry posts. Host logic is covered by the manual checklist; it is pure orchestration over tested core pieces.

### F4. Conversation compaction

**UX.** When the context is full, SOVRAN summarizes older turns instead of silently dropping them. The transcript keeps
every message for the user, with a divider: *"Earlier messages summarized for the model · Show summary"*. Compaction
can also be triggered manually (`/compact` or the context meter).

| Layer | File | Change |
|---|---|---|
| Core | `context/compaction.ts` *(new)* | `planCompaction(messages, keepTurns)` picks the summarized prefix (whole turns only). `renderForSummary()` produces a compact, tool-output-truncated transcript within a character budget. `summarize(provider, …)` streams a no-tools completion. The previous summary is folded into the new one |
| Core | `sessions/model.ts` | `Session.compaction?: { summary; firstKeptId; summarizedCount; createdAt }` |
| Core | `context/contextManager.ts` | Option `summary` injected into the system prompt |
| Core | `agent/agentRunner.ts` | Sends only messages from `firstKeptId` on. Auto-compacts when `buildContext` would drop turns (`autoCompact` setting). New `compact()` method for manual use |
| Host | — | `sovran.context.autoCompact` (default `true`). A run phase labelled "Summarizing" |
| UI | — | Divider with an expandable summary |

**Tests:** prefix selection respects turn boundaries. Auto-compaction triggers once and the next request carries the summary. Manual
compaction works.
**Risk:** a weak model writes poor summaries. *Mitigation:* a structured summary prompt (goal, decisions, files touched,
open tasks), and the user can still read the original messages.

### F5. ripgrep-backed search

| Layer | Change |
|---|---|
| Core `ports.ts` | Optional `WorkspacePort.searchText?(options)` |
| Core `search_files` | Uses `searchText` when available, else the JS scan. Protected paths are **always** post-filtered in core (defense in depth) |
| Host `adapters/RipgrepSearch.ts` *(new, no vscode import)* | Locates VS Code's bundled `rg` (`appRoot/node_modules{,.asar.unpacked}/@vscode/ripgrep/bin/rg`). Runs it with `--json`, `--max-filesize 1M`, `.gitignore` respected, protected globs excluded, killed at `maxResults`. Parses JSON (safe for Windows `C:` paths) |

**Tests:** an integration test against the system `rg` (skipped if absent). Core test that protected matches returned
by a port are still filtered.

## Wave 2 — Productivity

### F6. `@` file mentions and `/` slash commands (shared suggestion popup)

**UX.**
- **`@`**: typing `@sess` opens a popup of fuzzy-matched workspace files. ↑/↓ moves, Enter or Tab attaches the file as a chip, and Esc closes the popup.
- **`/`**: typing `/` at the start lists commands. Built-ins are `/explain`, `/fix`, `/test`, `/review`, `/doc`,
  `/compact` and `/new`. Custom commands come from `.sovran/commands/*.md` (trusted workspaces only). The transcript
  shows what the user typed (`/review src/a.ts`), and the model receives the expanded prompt.

| Layer | File | Change |
|---|---|---|
| Core | `util/fuzzy.ts` *(new)* | Subsequence scorer that rewards basename matches, word starts and contiguity |
| Core | `commands/slashCommands.ts` *(new)* | Built-in templates with `$ARGUMENTS`, `parseSlash()`, `expandCommand()`, custom-command parsing (description = first line) |
| Core | `sessions/model.ts` | `UserMessage.display?` (text as typed) |
| Host | `FileIndex` | Cached `findFiles` list invalidated by a file-system watcher, fuzzy-ranked top 20 |
| Host | — | Loads custom commands, `AppState.commands`. Expands `/cmd` on send. Handles the action commands (`/compact`, `/new`) |
| Protocol | — | `suggestFiles { requestId, query }` → `fileSuggestions`, and `attachPath { path }` (validated to stay inside the workspace) |
| UI | `Suggest` popup | Listbox with full ARIA (`role=listbox`, `aria-activedescendant`) |

**Tests:** fuzzy ranking, slash parsing and expansion, popup keyboard flow, attach post.

### F7. A model per mode

**UX.** Plan can use a different model from Act. For example, a large reasoning model plans while a fast coder
executes. In Plan mode the model button and the Quick Pick configure the Plan model, with a *Same as Act* option.

| Layer | Change |
|---|---|
| Settings | `sovran.planModel` (application scope, `""` means the same as Act) |
| Protocol | `AppState.planModel` |
| Host | `effectiveModel(mode)`. The Quick Pick title and the "Same as Act" item depend on the mode. Status bar shows the effective model |
| UI | The model button shows the effective model and a `Plan` / `Act` hint in its tooltip |

## Wave 3 — Extensibility & enterprise (next branches, design only)

| Feature | Design summary |
|---|---|
| **MCP client** | `McpToolSource` implements a tool provider that the registry merges in. Supports stdio and Streamable HTTP. **Config in user scope only** (a repository must never be able to launch processes). Every MCP tool has `risk:'execute'`, needs approval by default, and offers a per-server "always allow" option. Tool names are namespaced `mcp__server__tool`. Results are untrusted and truncated |
| **Admin-managed policies** | Read an organization policy file (path set by IT) and VS Code policy settings. It covers allowed `baseUrl` hosts, forced approvals, disabled auto-approve and disabled terminal. Policies override user settings, and the UI shows a "Managed by your organization" badge |
| **Native adapters** | A `ResponsesProvider` (OpenAI Responses API) and an `AnthropicProvider` behind the same `ChatProvider` interface. A capability matrix entry for each |
| **Usage panel** | Tokens and latency per run, tokens per second. Useful for comparing self-hosted models |

## Wave 4 — Reach

| Feature | Design summary |
|---|---|
| **Open VSX publishing** | Add an `ovsx publish` step to `release.yml`. This reaches Cursor, Windsurf and VSCodium users |
| **Copilot bridge** | A `LanguageModelChatProvider` that exposes SOVRAN providers inside Copilot Chat (optional, off by default) |
| **CLI** | `sovran` CLI on the shared core: ports implemented with `fs` and `child_process`, plus TTY approvals |
| **Image input** | Paste screenshots for vision-capable models (`image_url` content parts), gated by a per-model `vision` capability |
