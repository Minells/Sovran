# Architecture Decision Log

Short ADRs. Status values are *Accepted*, *Proposed* (awaiting owner approval) and *Superseded*.

| # | Decision | Status | Rationale |
|---|---|---|---|
| ADR-001 | Ports-and-adapters with a `vscode`-free core, enforced by ESLint | Accepted | Future CLI or other IDE reuse. Testability without the VS Code runtime |
| ADR-002 | The Extension Host is authoritative. The webview is a projection without `retainContextWhenHidden` | Accepted | Security (credentials and I/O stay in the host), lower memory use, survives webview disposal |
| ADR-003 | React 19 + Vite for the webview, with hand-built components on VS Code CSS variables | Accepted | The Webview UI Toolkit is deprecated (archived Jan 2025). Theme tokens give native theming including high contrast |
| ADR-004 | `apply_diff` = atomic search/replace blocks instead of unified diffs | Accepted | Local models are unreliable with line numbers and hunk headers |
| ADR-005 | Prompted tool protocol (`<tool_call>` JSON) as a fallback, with automatic downgrade on rejection | Accepted | Many OpenAI-compatible servers or models lack native tools |
| ADR-006 | Security-relevant settings are `application`-scoped and read from the global value only | Accepted | Blocks malicious repositories from redirecting credentials or auto-approving actions |
| ADR-007 | Writes go through `WorkspaceEdit`, with a staleness hash check | Accepted | Undo support, dirty-buffer safety, no silent overwrite |
| ADR-008 | Commands use `child_process` with a pseudoterminal mirror, not shell-integration execution | Accepted | Reliable output capture and exit codes on every platform. Shell integration is not always available |
| ADR-009 | Native `fetch` with a hand-written SSE parser, no OpenAI SDK | Accepted | Zero dependencies, full control over quirks, uses VS Code's patched fetch for proxies |
| ADR-010 | Sessions as JSON files in workspace storage with atomic writes | Accepted | globalState is not designed for large blobs. Scoping per workspace matches user expectations |
| ADR-011 | Model selection through a native Quick Pick instead of a custom dropdown | Accepted | Native, accessible, searchable and cheaper to build |
| ADR-012 | Core contracts before UI (milestone reorder) | Proposed (D7) | Avoids fake UI and rework |
| ADR-013 | No telemetry | Proposed (D4) | Product positioning |
| ADR-014 | Minimum VS Code `^1.95.0` | Proposed (D8) | Stable APIs used, `fetch` proxy support |
| ADR-015 | Command approval cards reveal invisible and bidi characters, and such commands never match the allow-list | Accepted | Prevents "Trojan Source"-style spoofing of what the user approves |
| ADR-016 | React state is derived during render instead of synchronized in effects (React 19 lint) | Accepted | Avoids cascading renders and stale UI |
| ADR-018 | MIT license | Accepted (owner decision D3) | Maximum adoption with minimal friction. All bundled dependencies are permissive. Note: MIT has no explicit patent grant, unlike Apache-2.0 |
| ADR-019 | Approval modes `ask` · `edits` · `auto` for Act mode. The mode is per window and starts from `sovran.approvals.mode`; turning on Auto needs a native confirmation once per window | Accepted | Mirrors the proven Claude Code model (per-session mode, explicit default). Per-window scope stops an Auto choice made in one repository from silently applying to the next. The native modal is informed consent and defense in depth against a compromised webview |
| ADR-020 | Guardrails beat every allowance: protected paths, high-risk command patterns, paths outside the workspace and hidden characters always ask, in Auto mode and for allow-listed commands | Accepted | Auto must stay recoverable: checkpoints undo file edits, but not a push, a deletion or a leaked secret. The patterns are heuristics, documented as not being a sandbox |
| ADR-021 | Provider requests never follow HTTP redirects (`redirect: 'manual'`) | Accepted | `fetch` keeps custom auth headers (e.g. `api-key`) and the POST body when following a redirect to another origin. A redirect becomes an actionable error instead |
| ADR-022 | Providers can also live in `~/.sovran/config.yaml`, kept in two-way sync with `sovran.providers`: the side that changed wins, the first sync joins both sides, the file is applied only when valid and never contains keys; it can be ignored or trashed | Accepted (revised: first shipped as a read-only overlay) | A text file suits people who version their setup; the panel suits everyone else, and users switch between them, so neither may lose data. Each side is written only when it differs (canonical comparison), which ends every sync after one round. The YAML document is edited in place to keep comments. Sovran never writes a file with problems or unsaved editor changes. The home folder keeps ADR-006's guarantee; keys stay in Secret Storage |
| ADR-024 | "API key" (`Authorization: Bearer`) is the labelled default auth; 401/403 errors say what the request carried; pasted keys are normalized; the connection test falls back to a chat ping on 401/403 from `/models` | Accepted | Gateway messages ("invalid key") do not tell a missing key from a wrong header or a wrong key, and each needs a different fix. Users coming from other tools pick "custom header" for "API key". Gateways often expose chat but not `/models` to a key |
| ADR-023 | Model-generated chat titles are on by default and run in parallel with the first request | Accepted (owner decision; first shipped opt-in) | Titles are worth the extra request for most users. The request goes to the chat's own model unless a title model is set, so no new endpoint sees the message by default. Up to 1024 tokens so always-reasoning models can answer; reading stops at the first line. The first-words title is shown at once and stays on any failure or rename; the setting turns it off |
| ADR-025 | Model limits: the user's value, else what the server reports, else 32 768 / 4 096. The window is taken as reported; a reported maximum output only caps the reply reserve. Ollama and llama.cpp limits are not read | Accepted | Matches the real window when the server knows it (vLLM, SGLang, LiteLLM, OpenRouter) without making the user look it up. A large reserve would shrink every conversation, so the reserve stays small unless the user raises it. Ollama and llama.cpp report the training context, not the runtime one, and overestimating the window fails silently. Reported limits live with the learned capabilities (globalState), never in settings or the file |
| ADR-017 | Release through GitHub Actions with Marketplace Trusted Publishing (OIDC) behind a protected environment | Accepted | Azure DevOps global PATs retire on 2026-12-01. No long-lived secret in the repository |
| ADR-026 | Documents (PDF, Office Open XML, OpenDocument, ZIP) are converted to Markdown locally, in TypeScript, in a worker thread per conversion: pdf.js for PDF, fflate and a minimal XML tokenizer of our own for the Office and OpenDocument formats. Not MarkItDown, not a service | Accepted | MarkItDown is Python, which a VSIX cannot assume or bundle, and its image path calls a model anyway. Local conversion keeps "nothing leaves your machine" and works offline. A small reader of our own covers every XML-in-ZIP format with one code path, no DTD or entity support by construction, and no large dependency tree. The worker isolates untrusted input (heap limit, timeout, termination) and keeps pdf.js's browser stand-ins and its 1.5 MB out of the extension host |
| ADR-027 | `pdfjs-dist` stays on `~5.4` while VS Code `^1.95.0` is supported | Accepted | pdf.js 5.5 and later need Node 20.19; VS Code 1.95 runs Electron 32 with Node 20.18. Verified with Electron 32.2.1 as Node and as a utility process (how the desktop extension host runs). Revisit when the minimum VS Code version moves |
| ADR-028 | Images for vision models: `image_url` parts with data URLs, only for messages that carry images; a per-model `vision` option, unset by default, with refusals learned like tool support; image bytes stored per chat outside the session file | Accepted | Plain-string content stays exactly what every server accepts. Servers rarely say whether a model takes images, so trying and learning from the refusal is the only reliable way, as with tools; size and count limits are not taken for a refusal, so a vision model is never downgraded by mistake. Megabytes of base64 in the session file would be rewritten on every save and sent to the webview with each snapshot; a content-addressed file per chat is written once and deleted with the chat |
| ADR-029 | `read_file` converts documents through the attachments' converter and a shared `DocumentReader` cache, and pages the Markdown by line | Accepted | The agent can use a specification or a spreadsheet in the repository without the user attaching it, with the same isolation and limits. Paging by line reuses the tool's existing parameters, so models need nothing new; the cache keeps paging from converting the file again |
| ADR-030 | MCP client on the official TypeScript SDK v2 (`@modelcontextprotocol/client`), wrapped by a core `McpHub` with injected transports (stdio and Streamable HTTP from the host, in-memory pairs in tests). No legacy SSE, no OAuth yet | Accepted (proposed for owner review) | v2 is the SDK's stable line (spec 2026-07-28), negotiates the 2025 handshake by default so it reaches today's servers, and follows redirects only within the same origin (ADR-021's rule for providers). Its client package has no web-server dependencies, and zod 4 is shared with Sovran. Injecting transports keeps child processes and sockets out of the core and lets tests drive a real SDK server without a process. It adds about 380 KB to the minified host bundle; loading it lazily is a possible later optimisation. SSE was deprecated by the spec in 2025 and OAuth needs a browser flow: both are left for a later step rather than half done |
| ADR-031 | MCP tools are `execute` tools that ask before every call in every approval mode, Auto included, until the user allows that tool; Act mode only; servers come from user settings only and start only in trusted workspaces; tokens in Secret Storage | Accepted (proposed for owner review) | An MCP tool acts outside the workspace, where no guardrail can read what it does and no checkpoint can undo it, which is why ADR-020 keeps such actions with a human. Annotations such as `readOnlyHint` are the server's claims, so they inform the user but never change the policy. A per-tool Off / Ask / Allow choice is precise enough to make Auto-like use possible for tools the user trusts, and *Off* also saves context on small local models. Starting servers only in trusted workspaces avoids a repository's local `node_modules/.bin` shadowing an `npx` command |
| ADR-032 | Native public URL fetch stays small; advanced browser work uses optional, locked MCP integrations with separate installation and Connect, profile tool bounds and no bundled browser | Accepted (owner direction, 2026-11-10) | The Crawlee spike is not adopted. Search/crawl/index remain deferred; browsers retain a separate privileged boundary from public-IP native fetch. Existing custom servers and permissions are preserved |
| ADR-033 | Persist per-chat group exclusions and estimate definition cost using the existing registry; enforce them at request and dispatch and consolidate controls in Tools | Accepted (P9 implementation) | Deterministic context reduction without an extra model call, silent tool eviction or a second registry. Old chats retain all groups; native global overrides and MCP policy still bound execution |
| ADR-034 | Tools load on demand by unit (`sovran.tools.loading: auto`, the default): the core is always offered; other units load when all definitions fit 10% of the input budget, from the chat's history, from a pattern router over the user's own message and slash command, through a runner-owned `load_tools`, or when the model calls an unloaded tool (which loads it and does not run). Units only accumulate during a chat and are appended after the core | Accepted (owner request, 2026-11-13) | Small local windows fill with tool definitions (about 4,800 tokens of native tools alone). Loading changes visibility, never permissions, and keeps the offered-definition check at dispatch. Append-only, stable ordering keeps server prefix caches valid; a deterministic router adds no latency or model call and cannot be steered by files or tool results. `all` restores the previous requests exactly |
